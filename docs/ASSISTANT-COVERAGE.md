# 助理覆蓋盤點（4.1.0）

本文件記錄懸浮 AI 助理能操作的範圍，供審查與後續補強使用。盤點以程式碼為準（`apps/desktop/src/main/assistant.ts`、`services/assistantTools.ts`、`assistantUi.ts`、`renderer/js/core/aiBridge.js`）。

## 架構

每一輪對話，畫面會送出「控制項目錄」：所有頁面中有 id 的欄位與按鈕（id、類型、標籤、目前值、選項）。目前頁面完整列出，其他頁面只列 id 與標籤。主程序只接受目錄中存在的 id，其餘一律拒絕。

| 類別 | 工具 | 執行方式 |
|---|---|---|
| 查詢（自動） | search_judgments、resolve_statute、read_judgment、list_saved | 直接執行，結果回給模型 |
| 畫面（立即） | open_page、ui_set、open_saved | 排入畫面更新，不呼叫 AI、不改動資料 |
| 提議（需同意） | propose_scope、propose_brief、ui_click、saved_action | 列為待確認，使用者按「同意執行」才執行 |

安全規則：
- 密碼、金鑰、權杖欄位只給 id 與標籤，**不給值，也不能填寫**（`SECRET_RE`：secret、token、passw、apikey、金鑰、密碼、權杖，以及設定頁的 `setKey`、`keyField`）。
- 按鈕一律需要同意；頁面鎖定中（處理流程進行中）的按鈕會拒絕。
- 目錄以 `[hidden]` 與 `data-ai-skip` 排除隱藏的控制項。
- 控制項 id 必須在所有頁面中唯一（測試 `控制項 id 在所有頁面模板中不重複` 會檢查）。

## 逐頁覆蓋

| 頁面 | 狀態 | 說明 |
|---|---|---|
| 首頁 | 完整 | 導覽由 open_page 處理 |
| 研究設計 | 完整 | 有獨立的多輪對話（工具：寫入欄位、試搜尋、帶入範圍整理）；欄位與按鈕也在目錄中 |
| 判決列表 | 大部分 | 關鍵字、法規、篩選與按鈕有 id；搜尋結果的逐列操作（AI 篩選後的勾選）為動態列，尚未列入 |
| 段落檢索 | 大部分 | 表單與按鈕有 id；結果的逐段操作為動態內容，尚未列入 |
| 標編碼標注工序 | 部分 | 表單與執行按鈕有 id；「分析欄位」的逐列編輯為動態列，尚未列入 |
| 納入排除 | 完整（輸入與執行） | 一句話輸入、AI 建議標準、個人標準組合、執行與結果；標準列由 AI 或手動加入後可逐列修改 |
| 單一判決精讀 | 部分 | 查詢與執行按鈕有 id；候選判決的「選定」為動態列，尚未列入；全文標注需要在文字上拖曳選取，無法由對話完成 |
| 量化圖表 | 大部分 | 圖表的欄位與按鈕有 id |
| 檔案 | 完整 | list_saved、open_saved、saved_action（星號、封存、移入垃圾桶、還原、永久刪除） |
| 工具／文本擷取 | 部分 | 關鍵字與各步驟按鈕有 id；選擇檔案需要系統對話框，助理只能請使用者自行選擇 |
| 設定 | 大部分 | 一般設定可由對話讀取與設定；金鑰與密碼由使用者自行輸入；儲存鈕有 id（setSave） |

## 尚未覆蓋的缺口（下一步）

1. **動態列**：標編碼的分析欄位列、納入排除的標準列（手動加入後）、單一判決的候選列、判決列表的逐列勾選。需要為每一列加上穩定的 id 或提供專用工具（例如 pick_candidate）。
2. **全文標注**：需要在文字上選取範圍，目前無法由對話完成。
3. **系統對話框**：選擇檔案、選擇儲存位置由作業系統處理，助理只能提示使用者。
4. **敏感資料**：金鑰與密碼刻意排除，這是設計上的限制，不是缺口。

## 驗證

- `npm test` 含 `assistant-ui.test.mjs`：目錄清理與敏感值隱藏、設值檢查（選項、勾選框、數字、按鈕、敏感欄位）、目錄文字、工具迴圈中畫面動作與待確認項目的收集、id 不重複。
